# Academic defense guide
Each block: problem, idea, why chosen, our code, limits, what to say.
**YOLOv8 (`pipeline.run_video`).** Single-stage detector: one network pass outputs boxes, classes, confidences (and keypoints for the -pose variant). Chosen for speed/accuracy and ready pretrained weights. Params: `conf`, `stride`. Limit: tiny fast balls. Say: "A single pass keeps latency low; the small ball is the known weak point, hence a dedicated detector plus Kalman."
**ByteTrack.** Associates detections across frames with IoU matching and keeps low-confidence boxes in a second matching round, which reduces identity loss in occlusions. Ours: `pm.track(..., tracker="bytetrack.yaml")`. Limit: ID switches when players cross.
**Kalman filter (`ball.BallKalman`).** State x=[x,y,vx,vy]. Predict: x=Fx, P=FPF^T+Q. Update: K=PH^T(HPH^T+R)^-1, x=x+K(z-Hx), P=(I-KH)P. Gate radius 120(1+gap) px, max_gap=8, then reset. Why: fills short misses, flags them `observed=False`. Limit: constant-velocity model is wrong at bounces and hits.
**Homography (`court.court_homography`).** A plane-to-plane map solved by DLT: each corner gives 2 linear equations, SVD gives h (8 dof, 4 points). Valid only for points on the ground plane, so we use the bottom-centre of the box (feet). Errors grow with corner-click error and distance. Say: "Distances in metres are only claimed when calibration exists."
**Pose and angles (`pose_utils.extract_features`).** Angle at joint b between a and c: arccos(u.v/|u||v|), u=a-b, v=c-b. Heights are divided by torso length so they do not depend on camera distance. Low-confidence keypoints are NaN, windows with NaN become `Uncertain`.
**Rule-based strokes (`pose_utils.classify`).** Wrist above head + straight elbow + fast downward swing = smash; above head otherwise = bandeja; bent knees + fast upward swing = lob; compact = volley. Thresholds are hypotheses. Honest claim: consistent on synthetic skeletons, unvalidated on real play. Next step: labelled strokes, then a temporal classifier compared with this baseline.
**Ball events (`events.detect_events`).** Velocity before/after a point from +-3 samples; a large angle change at sufficient speed is a candidate. Floor bounce: vertical reversal in image space; rebound: horizontal reversal. Confidence = angle/120 x observed share. Limit: a single camera cannot separate racket, wall and floor reliably.
**TF-IDF + cosine (`reco.TfIdf`).** weight = tf x (ln((1+N)/(1+df))+1); similarity = cosine. Transparent, needs no interaction data. Why not NeuMF: it needs many user-item interactions; the thesis' HR@5=0.66 came from a very small user base. Catalog here is synthetic.
**Identity (`identity.py`).** ArcFace-style embeddings are L2-normalised; match = max cosine, accepted only above a threshold, else unknown; `TrackVote` needs 3 identical matches; consent mandatory; delete cascades. Limit: placeholder threshold, no liveness detection implemented, biometric privacy duties.
**Database (`db.py`).** Normalised tables with foreign keys, index on (session, track); videos stay on disk.
**Evaluation (`evaluation.py`).** Strokes: confusion matrix, per-class precision/recall/F1, coverage excluding Uncertain. Ball: recall and pixel error versus labels. Split by video to avoid leakage between adjacent frames.
**Critique of the original thesis you can raise.** Tab. 3 divides 0.48 m by 0.04 s although it states dt=0.12 s (gives 4 m/s, not 12); the dashboard shows 75 m/s; the ball is not tracked; evaluation is thin.
**If asked "why rebuild with these choices?"** "Each module is replaceable behind a simple data contract, and every claim is tied to a test or marked as unverified."
**Collaborative filtering (`cf.py`).** User-based: score = sum(sim x rating)/sum(|sim|) over the k most similar users who rated the item; SVD: low-rank reconstruction of the mean-filled matrix; hybrid = 0.5 x UB + 0.5 x SVD (thesis eq. 20-21). Evaluation: leave-one-out HR@k. Our test uses synthetic ratings, so it only shows the code works; the thesis' HR@5 = 0.66 came from a tiny user base.
**NeuMF (`neumf.py`).** GMF (element-wise product of embeddings) + MLP (concatenated embeddings) fused into a sigmoid score, trained with BCE, negative sampling, Adam, 80/20 split, early stopping. The code refuses to train below 200 interactions. Say: "I implemented it but I do not claim results: there is no real interaction data."
**TrackNet-style detector (`tracknet.py`).** Stacks 3 consecutive frames so motion reveals a tiny blurred ball, and predicts a heatmap decoded by argmax + threshold. Ours is a small U-Net-like model checked only on synthetic moving blobs (when torch is available); real use needs PadelTracker100 or similar labelled data.
**Datasets.** See `DATASETS_AND_MODELS.md`: PadelTracker100 (CC BY 4.0, two WPT matches, COCO JSON) is the main labelled source for ball, pose and shot events; domain gap to club cameras must be measured.
